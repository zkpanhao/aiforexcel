# AI for Excel · Office.js

在 Excel 任务窗格中输入要求，针对发送时选区直接执行，支持“恢复上一步”。这是开发试用版；现有 VBA 加载项保留。

日常使用采用固定目录的本地安装版，安装、更新、回退和两台电脑协作流程见根目录 [`update.md`](../update.md)。根目录 `manage-local.ps1` 为操作入口；下面的 `npm start` 仍是开发测试侧载，不代表所有新工作簿自动加载。

## 已实现

完整说明见项目文档目录 [`docs/功能清单.md`](../docs/功能清单.md)。

- 写入文字、数字和公式；清除内容；原生清除单元格格式（含字体、字号、填充和边框）。
- 大区域值、公式和新表数据自动分批写入，每批最多 2000 格；状态栏显示进度，可取消并恢复整轮修改。文本空白、不可见字符及明确指定的占位符可在本机分批清理，无需由模型逐格重写数据。
- 设置字体名称/字号/颜色、加粗/斜体/下划线、填充、对齐、数字格式、换行和多种边框；调整行高列宽或自动适应。
- 合并/拆分、排序/筛选、数值/文字/公式/色阶/数据条条件格式；创建柱形、条形、折线、饼、面积或散点图。
- 在新表创建透视汇总；在工作表副本中插入/删除整行整列；按要求新建工作表。
- 发送时固定选区上下文。等待期间改选区域不影响本轮目标；原选区数据被改动时停止执行。操作可按模型给出的精确地址写入选区外或其它工作表。
- 用 Excel 原生复制保存隐藏备份；执行报错时尝试自动恢复；手动恢复最近一轮。
- 统一对话入口，按本轮意图直接分析或修改，必要时自动分步；请求可取消，选区/API/执行分段计时；模型列表刷新和手工输入模型名。
- 需要按依赖顺序处理的要求会自动进入分步任务：先生成 1–8 步计划，逐步执行并读回结果检查；支持暂停、继续、补充要求后从指定步骤重做、逆序撤销整个任务。
- 在输入框旁保存和选择本机常用命令；点击命令追加到现有输入末尾，右键提供“修改”和“删除”。修改使用独立多行编辑框，可保存或取消，不改动聊天草稿。命令保存到安装目录 `user-data/common-commands.json`，更新保留且 Git 忽略；文件不存在时迁移旧缓存，已有文件优先，防止删除/修改后被旧缓存恢复。每次变更保留上一版 `.bak`。最多 50 条、每条 2000 字符；文件操作失败明确报错，重复或已被其它窗格改动的命令会提示处理。
- 支持连续追问，保留当前窗格最近 10 轮、合计最多 40000 字符的对话摘要；无需选择工作模式。点击“清除对话”开始新对话，保留表格内容、恢复记录、分步进度和未发送文字；执行中暂不能清除，重开窗格也会重置对话。
- 模型响应允许在唯一完整 JSON 外附说明或代码围栏；语法失败时自动重新生成一次（最多额外一次 API 请求），仍执行严格参数校验。截断、拒绝及非法操作直接停止，不执行残缺结果。
- 接口传输量与最终输出分别限制：流式协议包装和未展示的推理内容不再占用最终答案的 600000 字符额度；单次传输最多 64 MiB，单条流式消息最多 4 Mi 字符。超限提示会区分传输、单条消息与最终输出，立即停止读取，本次响应不会执行。

只询问、分析或解释时应直接回答，不擅自写入。模型返回 read_only:true 后，插件会拒绝写入或分步决定，补充数据/格式时继续保持只读；下一条明确要求修改时可以执行。判断意图使用同一次模型请求，不额外增加分类请求。所有请求统一不设置固定等待截止时间，可主动取消。语义判断仍需真实模型验收。

## 连接默认值

| 配置 | 地址或名称 |
| --- | --- |
| Base URL | `https://jxai.keloom.com/v1` |
| 模型列表 | `https://jxai.keloom.com/v1/models` |
| 默认模型 | `gpt-6.1-sol` |

连接设置支持内置供应商：OpenAI（`https://api.openai.com/v1`）、DeepSeek（`https://api.deepseek.com`）、Qwen/通义千问（DashScope 兼容模式）、GLM/智谱（`https://open.bigmodel.cn/api/paas/v4`）和 MiniMAX（`https://api.minimax.io/v1`）。这些接口使用 OpenAI 兼容的 `chat/completions` 请求格式；供应商选项会自动填入对应 Base URL 和一个可修改的默认模型。模型列表能力由供应商决定，获取失败时仍可手动输入模型名称。选择“自定义 / 中转”即可继续使用自己的兼容中转地址。

API Key 在窗格“连接设置”中输入。地址、模型、供应商和是否记住密钥保存到本机安装目录 `user-data/connection.json`，不再依赖 Excel 网页缓存；整个目录由 Git 忽略，插件更新保留。首次打开会迁移旧缓存；已有文件优先，成功后移除旧连接键，避免旧缓存复活已清除的密钥。

勾选“记住密钥（仅此设备）”才将密钥保存到该文件并在重开窗格时填回；未勾选只在当前窗格内存使用。“清除已保存密钥”保留地址和模型，删除文件中的密钥；`.bak` 只备份不含密钥的连接信息。更换接口或供应商时清除原密钥，不自动复用。JSON 采用原子替换，损坏或写入失败时保留原文件并明确报错；保存请求按顺序执行，避免快速输入和清除操作乱序。密钥未额外加密，不写入工作簿、项目、日志或同步文件；其它设备需独立配置。

每次任务都会发送当前选区、输入的要求及近期问题和结果摘要；大选区首轮只发送位置、尺寸和数量。对话仅存在当前窗格内存，不写入本机文件或工作簿；独立的分步任务进度仍随工作簿保存。

## 开发与加载

需要 Node.js 22.18+ 或 24，以及支持 ExcelApi 1.13 的 Microsoft 365 Excel。

```powershell
cd 'D:\AI For Excel\officejs'
npm ci
npm run typecheck
npm test
npm run build
npm run validate
```

本地 HTTPS 证书由微软 Office 开发工具管理。首次启动可能出现 Windows 证书安装提示，它用于信任本机 `localhost` 开发页面。

```powershell
npm start
```

启动命令会启动本地服务并尝试将 manifest 侧载到桌面 Excel。Excel“开始”选项卡出现“AI for Excel → 打开 AI 助手”后，输入密钥，选择少量测试单元格，再发送要求。

单独启动页面服务：`npm run dev`。调试页面为 `https://localhost:3000/taskpane.html`，普通浏览器不具备 Excel 工作簿连接。`npm start` 在后台隐藏运行服务，并验证实际 HTTPS 响应，避免把关闭中的端口误判为已启动。停止调试并注销本次侧载：`npm stop`；单独用 `npm run dev` 启动的服务需在原终端结束。

公司策略可能禁止开发加载项或证书安装；此时应由管理员允许开发侧载或部署加载项，不能绕过策略。不要为开发关闭宏保护或 Office 安全策略。

## 当前边界

- 一次最多读取 100000 格。100 格以内首轮直接把完整值/公式发给模型；超过 100 格首轮只发送工作簿、工作表、地址、行列尺寸和单元格数量，由模型判断是否需要读取内容。模型明确需要时，插件才读取原选区并发起第二轮请求；不需要时直接返回操作。第二轮完整数据仍受 100000 格和请求长度限制。值/公式、新表数据及文本清理的单个目标最多 100000 格，一轮区域处理量累计最多 200000 格；2000 格是自动提交批次大小，不是任务总上限。模型请求/响应和操作计划的文字体积限制仍然生效，大区域规则化清理使用紧凑的本机规则。
- `transform_text` 支持去除所有空白、只去首尾空白、合并连续空白；可另去除零宽空格 U+200B、word joiner U+2060 和 BOM，或按明确文字替换（可限定整格相等）。仅修改文本常量，保留数字、布尔值、公式和格式，保留清理后订单号的前导零及长文本类型。不猜测“占位符”含义，未明确字符时先询问，不默认删除 0、- 或 N/A。
- 支持连续区域和完整包含的合并区域；写入、排序、筛选和条件格式需先拆分合并单元格。Excel 表格内仅开放格式、图表、透视和结构副本；数组/溢出公式、受保护区域仍不修改。操作目标不再受当前选区或工作表限制；跨工作表目前支持值/公式写入，目标已有内容时会显示覆盖提示。
- 行列插删在新工作表副本中单独执行，保留原表。条件格式仅添加到尚无规则的选区。筛选最多 2000 行，尺寸调整最多 2000 行/500 列。任意 VBA、宏或脚本不开放。每次发送重新读取本轮选区；对话历史提供意图、目标与执行状态，不缓存旧单元格矩阵，不重放旧操作，也不把历史结果当成当前表格数据。
- 恢复会还原本轮实际修改的每个目标区域，并删除该轮新建的工作表。会覆盖这些区域在操作后的手动修改；只支持最近一轮。
- 直接“处理表格”的恢复按钮记录保存在窗格内存中，刷新/关闭窗格后不可用。分步任务的计划、状态和声明式恢复记录保存在当前工作簿的加载项设置中，备份仍在隐藏工作表内；需要保存工作簿才能写入磁盘，不会自动保存业务工作簿。分步任务不保存连接密钥，恢复后不会自动继续执行。
- 原生区域复制备份单元格内容、格式和合并状态；另外保存该轮涉及的行高列宽和筛选状态，并追踪本轮创建的图表/输出表。恢复移除本轮新对象，不改动用户已有图表；结构副本的恢复是删除新副本。

## 分步任务

选中原始数据后输入完整要求并点击“发送”。插件通过当前模型判断是否存在需要逐步检查的结果依赖；简单任务直接执行，需要分步时自动规划。用户无需选择复杂程度。计划展示后自动逐步推进；每步执行前保存恢复记录，执行后读取真实值、公式和对象，再由模型检查该步的业务目标。

某一步失败或检查不通过时停止后续步骤，保留已完成步骤。点击“继续 / 重试”会先恢复未完成步骤，再从该步继续。补充要求填在任务面板中，再点相应步骤的“从此步重做”；该步骤及之后的步骤先逆序撤销，前面的结果保留。暂停会取消模型等待；已提交但未完成检查的步骤保留备份，继续时先恢复再重试。

“撤销整个任务”按逆序恢复所有步骤；“保留结果并结束”保留现状并释放该任务的恢复记录。每个工作簿同时保留一个分步任务；任务存在时可在同一输入框提问或分析，插件强制只读；修改通过任务面板继续/重做，或先结束任务后再提出。执行时使用当前连接设置，密钥不随任务保存。

继续及重做会检查已记录区域的值、公式、逐格基本格式、行高列宽、隐藏状态、合并状态和相关图表/筛选等信息。发现变化会停止，避免覆盖手动编辑；复杂对象的全部属性尚不能完整检测。执行中关闭窗格后，需先恢复中断步骤，该恢复可能覆盖该步骤区域内后续手动修改。保留工作簿及备份，不要手动删除 `_AI_backup_…` 表。

每步操作仍受原白名单、范围和保护校验约束。模型检查最多接收 2000 格结果样本，大结果明确标记为部分读取；独立文本清理步骤可另提供与备份逐格核对的全量结果摘要。证据不足时应暂停，不保证模型一定正确。分步任务通常增加模型请求次数和等待时间；规划与检查沿用当前供应商的兼容接口，不执行模型生成的脚本。
