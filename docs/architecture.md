# Office.js 当前实现

## 请求与执行

1. 选区变化事件防抖后只读地址；发送时再捕获选区、工作表 ID 和尺寸，最多读取 100000 格。
2. 发送首轮只发送地址、尺寸、工作表和单元格数，不预读单元格值/公式。模型返回 `needs_data:true` 时，插件按首次发送的工作表 ID 与地址读取完整原选区，再发起后续请求；返回 `needs_format:true` 时只读取格式，不读取值/公式。模型可以在 `data_request.ranges` 中声明当前选区以外的参考区域，插件按工作表名称和地址读取后放入 `selection.supplemental_ranges`。发送前在不同工作表依次选择的区域不会自动合并；涉及参考表补充、匹配或回填时，要求中应明确参考工作表和连续地址。按源行或源区域复制格式使用原生 `copy_formats`，只读取并修改格式，不读取目标区域内容。
3. 工作窗格使用统一对话入口，无模式选择。askAgent 在同一次请求中判断本轮分析/修改意图及是否需要分步：分析用 read_only:true 和空 operations，修改用结构化操作，依赖任务返回 needs_workflow。parseTurn 拒绝只读混入写入或分步决定；taskpane 将只读约束保持到本轮数据/格式补充结束，下一条用户请求重新判断。有已保存分步任务时输入框强制只读，原任务通过面板管理。所有请求可取消，不设置固定截止时间；最多保存当前窗格最近 10 轮、40000 字符的对话摘要，清除或重开窗格重置。通过供应商预设或自定义 HTTPS Base URL 请求兼容 chat/completions 接口，预设包含 OpenAI、DeepSeek、Qwen、GLM 和 MiniMAX。
4. 校验操作白名单、地址、矩形数据尺寸、格式参数和累计处理量，不执行任意代码。选区只作为模型上下文，不再作为目标范围边界；值/公式写入限制 2000 格，清除或格式操作允许较大连续区域。
5. 通过工作表 ID 定位原表，检查保护、复杂区域、同名新表与数据是否过时。
6. 在一个或多个非常隐藏的 `_AI_backup_…` 表按目标工作表和地址用 `copyFrom(All)` 备份本轮会修改的区域；先同步备份，再批量修改。目标可以超出选区或位于其它工作表，恢复时逐个目标复制回去。
7. 成功后更换最近一次恢复记录并清理旧备份。失败时尝试复制回各目标区域并删除本轮新表；恢复失败保留记录。

`context.sync()` 是必要的批处理边界：读取元数据、读取数据、执行前检查、同步备份、提交修改。不能为了减少同步而在备份完成前写入。

## 当前工具

`write_values`、`write_formulas`、`clear_contents`、`clear_formats`、`format_range`、`copy_formats`、`copy_visible_values`、`lookup_replace`、`create_sheet`。精确类型与校验见 `src/tools/protocol.ts`，模型说明见 `src/llm/client.ts`。

文字写入对可能被解释为公式的前缀转义；`null` 转成空串以清空，避免 Office.js 将 null 解释为跳过。公式写入单独校验。

## 恢复语义

### 分步任务

`state/workflow.ts` 管理最多 8 步的任务状态机。`llm/workflow.ts` 分别请求计划与结果检查，单步操作仍走 `askAgent` 和严格的 `parsePlan`。每个步骤读取自己的明确工作表及范围，提供此前步骤的实际结果，不重复已完成步骤。

执行器的 `retainUndo/checkpoint` 选项在原生备份同步完成后、业务修改开始前保存声明式 `UndoSnapshot`。普通直接处理仍只保留最近一轮；分步执行不清理前面步骤的备份。`excel/recovery.ts` 从保存的工作表 ID、原生备份、创建对象与扩展元数据重建恢复能力，不依赖原页面闭包。

`state/workflow-store.ts` 使用文档级加载项设置保存当前任务（计划、状态、结果摘要、区域指纹和恢复元数据），不保存连接或 API Key，不把原始单元格复制到本地磁盘。工作簿必须由用户保存才能持久化到磁盘。刷新后只展示进度；检测到执行/恢复中断时要求先恢复再继续。

## 本地错误日志

任务窗格遇到执行错误时向本机宿主提交受限诊断记录，宿主追加到安装目录的 `logs/client.log`，超过 2 MB 后保留一份轮转文件。记录只包含版本、阶段、错误文本、选区和操作地址/类型；不包含用户提示词、单元格值、公式、连接地址或密钥。开发模式写入 `work/client.log`。

每步提交后读回目标值、公式、图表等证据，先检查写入不一致及 Excel 错误，再请求模型核对业务标准。证据预算 2000 格，超出明确标注不完整。校验失败保留当前步骤备份并暂停，不自动无限重试。

重做从末尾向指定步骤逆序恢复，先持久化进度再释放对应备份，随后重新生成该步及后续步骤。暂停在模型等待阶段取消；Excel 已提交但未完成检查时保留本步备份，继续时先恢复再重试。Web Locks 防止同一任务在两个窗格同时执行。继续/重做前对记录区域做分批指纹检查，发现手动修改即停止；进度存储不等同完整工作簿备份，复杂对象的全部属性仍不保证检测。

原生区域备份用于保留各单元格不同的字体、字号、边框、填充、数字格式、值和公式。新表带本轮唯一标记，恢复时仅删除属于本轮的表；成功后使用 ID 跟踪，支持新表改名。

普通直接处理的恢复记录仅在当前窗格会话内有效；分步任务使用上述文档级进度和声明式恢复记录。原始表若被删除、受保护或结构已大幅改变，恢复可能失败；不能把隐藏备份视为完整工作簿备份。

## 性能

按二维数组批量写入，不逐格跨宿主调用；点击选区不请求模型。界面分别计时读取、模型和执行阶段，并在底部显示模型阶段的实时秒表；秒表显示期间表示模型请求链路尚未结束。Office.js 的优势在宿主集成和部署方式，不能据此推断一定比 VBA 快。


## 本机用户文件

安装目录 user-data/ 独立于不可变 releases/，由 Git 忽略，更新不覆盖。common-commands.json 保存常用命令，connection.json 保存连接及用户选择记住的密钥；HTTP 服务仅开放固定同源专用接口，静态文件白名单不提供此目录。连接接口另要求自定义请求头、同源 POST，服务不记录请求正文或配置内容。

state/connection-file.ts 串行提交连接变更，启动时优先读文件，仅文件不存在时迁移旧 localStorage；确认落盘后移除旧连接键，已有文件不会被旧缓存覆盖。密钥未勾选时不发送给文件接口，清除保留其它设置；服务读取时核对密钥绑定的 Base URL。原子保存使用临时文件、fsync 和替换；损坏文件不自动覆盖，备份仅保存不含密钥的设置，防止取消记住后密钥留在备份里。模型仍由窗格直接请求供应商，服务不代理模型请求。
