# AI for Excel 协作约定

## 用户的工作方式

- 用户通过 ChatGPT/Codex 提出功能需求，由助手完成代码修改、检查、测试及当前电脑的 Excel 插件加载。
- 不要求用户日常手动执行命令或双击脚本。必要的系统授权、证书确认及无法自动处理的界面由用户操作。
- 新聊天先读取本文件、`docs/UPLOAD_RULES.md` 和 `officejs/README.md`；测试时参考 `docs/testing.md`。
- 本地安装及更新以根目录 `update.md` 为准，使用 `manage-local.ps1` 入口；日常运行使用生产构建的本地安装版。
- 后续需求记录在 `docs/TODO.md`；按用户指定的优先级维护，不自动实施尚未安排的事项。
- 当前对模型开放的能力及边界见 `docs/功能清单.md`；新增能力必须同时维护参数校验、模型说明、执行和恢复，不能仅修改提示词声称支持。
- 使用中文沟通，说明结果、验证情况和剩余问题。不得把“启动命令成功”当作“Excel 实际加载成功”。

## 两台电脑与 GitHub

双机切换、GitHub 提交/推送/拉取、冲突处理和本地安装边界见 collaboration.md。按用户要求，直接使用当前目录 D:\OneDrive\learn\coding\AI For Excel 同步 GitHub，不另建工作副本，不切换到 D:\Projects\AIForExcel。开始工作前检查 Git 状态及远端，不覆盖未提交修改，不强制推送。

## 当前电脑的环境与启动

- 优先统一使用 Node.js 24；检查实际运行版本，避免误用旧版本。若借用已有兼容环境，核实路径和版本，不依赖另一台电脑的安装位置。
- 首次使用本地运行副本，或 `package.json` / `package-lock.json` 变化时，按锁定版本安装依赖。项目 `.npmrc` 必须一起保留。
- 优先使用 `npm ci --registry=https://registry.npmjs.org/`。此前镜像源曾缺少所需安装包；不要为此随意升级依赖或改写锁文件。
- 每台电脑独立安装开发证书、注册 Excel 插件，并在使用期间运行本地 HTTPS 服务。GitHub 同步不会同步这些安装状态。
- 注册清单应指向当前本地运行副本的 `manifest.xml`。首次从 OneDrive 运行迁移到本地副本时，核对并更新注册和服务来源，避免继续使用旧路径。
- 启动前检查端口 3000 上的服务及其所属项目；不能只凭网页标题判定服务来自最新运行副本，也不能关闭来源不明的服务。
- 普通功能更新后，确保本地副本已更新并重新编译，必要时重新打开任务窗格。修改插件清单、按钮、权限或清单路径后，重新注册/加载并验证入口。
- API Key 由用户在各电脑的插件界面配置，不写入项目、脚本、测试数据、日志或同步文件。
- 文件系统及系统操作继续遵守当前工具的权限要求；本文件不授予绕过授权或安全设置的权限。

## 功能修改与验证

- 先检查现有实现和相关说明，再进行必要修改。只处理当前需求，不顺带升级所有依赖。
- 对功能代码改动，运行适用的类型检查、自动测试和构建：`npm run typecheck`、`npm test`、`npm run build`。修改清单时再运行 `npm run validate`。
- 纯文档改动检查内容及路径即可，不必启动 Excel 或运行整套测试。
- 自动检查完成后，将最新源代码更新到当前电脑的本地运行副本，确认构建和服务使用的是这一版本。
- Excel 实测只使用新建或专用测试工作簿，不在用户业务工作簿中做破坏性验证。不关闭用户其它工作簿或丢弃未保存内容。
- 按改动选择 `docs/testing.md` 中的验收项。涉及单元格修改时检查“恢复上一步”；涉及模型连接时，需要真实 API 请求才能确认端到端成功。
- 区分“自动检查通过”“Excel 宿主验证通过”“真实模型请求通过”，未执行的验证明确说明。检查本地状态文件时核对时间，不能把历史结果当作本次成功。
- 直接处理仅支持最近一轮恢复，刷新或关闭窗格会丢失内存记录；分步任务在文档级加载项设置保存进度和声明式恢复记录，需保存工作簿才能写入磁盘。执行器改动必须同时验证直接恢复和分步逆序恢复；有待恢复操作时先处理，再刷新或重启。
- 完成后用中文简要报告修改内容、已完成的验证、当前电脑加载状态及需要用户处理的事项。

## 常见用户指令

- “增加这个功能并测试”：修改当前 Git 工作副本中的源代码，完成适用检查，再更新当前电脑运行副本并验证。
- “同步最新代码并启动 Excel 插件”：检查本机同步与环境，将源代码更新至本地运行副本，必要时安装依赖，启动并核实插件加载。
- “在另一台电脑继续”：读取本文件并重新核实本机路径、依赖、证书、插件注册和服务，不假定上一台电脑的状态在本机存在。
