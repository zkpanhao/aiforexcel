# 双机协作与 GitHub 同步

源代码使用 GitHub 私有仓库同步，直接使用当前项目目录。本机目录为 D:\OneDrive\learn\coding\AI For Excel；按用户要求不另行创建副本，也不切换到 D:\Projects\AIForExcel。

## 目录与同步边界

- Git 工作副本：由当前工作区解析，不硬编码另一台电脑的路径。
- 本机安装目录：%USERPROFILE%\AIForExcel\officejs，每台电脑独立安装。
- 仓库保存源代码、测试、图标、公开清单和项目文档。
- 根目录 .gitignore 排除依赖、构建输出、日志、业务工作簿、密钥、证书及本机安装状态。
- 依赖由 officejs/package-lock.json 和 .npmrc 重建，不复制其它电脑的 node_modules。
- 当前目录同时位于 OneDrive 中。Git 操作时避免两台电脑同时修改或同步 .git；出现同步冲突时先核对，不覆盖本地修改。

## 在一台电脑完成工作

1. 开始修改前检查当前分支、远端及未提交内容，拉取远端最新版本。存在本地修改时先保留并核对，不直接覆盖或清空。
2. 完成功能修改和适用验证，按 update.md 更新本机插件。
3. 检查将提交的文件，确保不含密钥、证书、日志或业务数据；将相关源码、测试和文档提交为一条清晰的版本记录。
4. 推送到 GitHub；确认远端最新提交与本地一致，再切换到另一台电脑。

日常可让助手完成这些操作，无需手动运行命令。涉及新的 GitHub 登录或系统授权时由用户操作。

## 在另一台电脑继续

1. 首次使用时登录 GitHub，在用户指定的当前项目目录连接同一私有仓库，不另建副本；以后先检查 Git 状态再拉取最新版本。
2. 读取 docs/AGENTS.md、本文件及 update.md，确认当前提交与待处理事项。
3. 核实本机 Node.js 24；依赖缺失或锁文件变化时在 officejs 按锁文件安装依赖。
4. 按 update.md 执行本机安装或更新，独立检查证书、清单、登录启动项、服务版本及 Excel 加载状态。
5. API Key 由用户在本机插件界面配置，不从 GitHub 或另一台电脑复制。

## 冲突和检查

- 两台电脑尽量轮流修改；同步前检查未提交内容，不强制推送、不清空工作区。
- 拉取遇到冲突时比较两边变更并合并，完成检查后再提交；不能以覆盖整个目录代替处理冲突。
- 本机默认只允许快进拉取；需要合并时明确检查双方改动后处理。
- 同步完成以远端提交和本地提交一致为准，不能仅依据“推送命令已启动”。
- GitHub 推送不会自动触发另一台电脑安装插件，也不会同步证书或本机连接设置。
- 功能和本机安装结果继续记录在根目录 update.md；提交本身不代表 Excel 宿主已验证。

本项目远端仓库：https://github.com/zkpanhao/aiforexcel.git；默认分支为 main。
